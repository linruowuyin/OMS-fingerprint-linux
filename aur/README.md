# Arch Linux packages

Two package flavours are maintained here:

| Package | For |
|---|---|
| `libfprint-omsmoc` | **Generic** — works on any machine with the `33a7:2388` sensor |
| `libfprint-omsmoc-wujie14pro` | Tuned for the Mechrevo Wujie 14 Pro (same driver, machine-specific metadata) |

Both build `libfprint` 1.94.100 from the upstream tarball with the OMS driver
patched in. The driver is compiled **into** `libfprint-2`, so the package
*is* a libfprint package.

> **You do not need an AUR account to use these.** Clone this repository and
> run `makepkg` — see [docs/INSTALL.md](../docs/INSTALL.md).

```
aur/libfprint-omsmoc/
├── PKGBUILD            # libfprint 1.94.100 + omsmoc driver
└── .SRCINFO            # generated by makepkg --printsrcinfo

aur/libfprint-omsmoc-wujie14pro/
├── PKGBUILD
├── .SRCINFO
└── source-repo/        # the patch is hosted here, not inside the package
```

The driver patch is **not** shipped inside the package directories — AUR only
accepts source packages and rejects local files. It is fetched from
<https://github.com/linruowuyin/omsmoc-patches> at build time, pinned to a tag.

## Build and install locally

```bash
cd aur/libfprint-omsmoc
makepkg -fC            # build (always add -C, see below)
# install (pacman will ask to remove the distro libfprint; answer y)
yes | sudo pacman -U libfprint-omsmoc-*.pkg.tar.zst
sudo systemctl restart fprintd
fprintd-list          # the device should appear
```

> `-C` is required on every rebuild: without it `prepare()` fails because the
> patch is already applied to the cached source tree.

> `makepkg` writes `src/`, `pkg/`, the source tarball and `*.pkg.tar.zst` into
> the package directory. None of that is tracked in git — `.gitignore` covers
> `aur/*/src/`, `aur/*/pkg/`, `*.pkg.tar.zst` and `*.tar.gz`.

### Packaging details (learned the hard way)

* `provides` must include the soname:
  `provides=('libfprint' 'libfprint-2.so=2-64')`, otherwise `fprintd`'s
  `libfprint-2.so=2-64` dependency cannot be satisfied and the install fails.
* `conflicts` must be version-limited: `conflicts=('libfprint>=1.90')`. The
  system may also carry the legacy `libfprint-1` (which provides
  `libfprint=1.0` and is depended on by `fingerprint-gui`); a blanket
  `conflicts=('libfprint')` would remove that too and abort the install with a
  broken dependency.
* `check()` runs `meson test -C build omsmoc-proto` — the 14 frame-codec test
  cases run as part of the package build, so a broken patch fails the build
  instead of shipping.

### The build-path problem

`libfprint`'s `fpi-device.c` includes `tests/fpi-test-emulation.h`, a file
generated by `meson configure_file` that hardcodes the absolute build
directory. That string constant ends up inside the shipped
`libfprint-2.so.2.0.0`, leaking the builder's home directory into the binary.

`-ffile-prefix-map=$PWD=.` does **not** fix it — that is a compile-time macro
substitution and cannot rewrite a string produced by `configure_file`. The
packages therefore rewrite the generated header and recompile:

```bash
emulation_header=build/tests/fpi-test-emulation.h
build_dir=$(sed -n 's|^#define FPI_EMULATION_HELPER_BUILDDIR "\(.*\)"$|\1|p' "$emulation_header")
if [[ -n "$build_dir" ]]; then
    sed -i "s|$build_dir|/usr/libexec/libfprint-2-tests|" "$emulation_header"
    meson compile -C build
fi
```

Keep this block in `build()` when updating the packages, and verify afterwards:

```bash
! strings pkg/*/usr/lib/libfprint-2.so.2.0.0 | grep -q "/home/"
```

## After installing

Restart `fprintd` (or let D-Bus activate it), then:

```bash
fprintd-enroll     # press and lift the finger six times
fprintd-verify     # press once
```

Expected: `enroll-completed` and `verify-match (done)`. An unenrolled finger
must return `verify-no-match`.

Uninstall and return to the distribution package:

```bash
sudo pacman -R libfprint-omsmoc
sudo pacman -S libfprint
```

> ⚠️ This package `provides`/`conflicts` with `libfprint`: it **replaces** the
> distribution's libfprint. A distribution upgrade of libfprint will report a
> conflict — rebuild and reinstall this package, or wait until the driver is
> merged upstream. gtk-doc is disabled (`-Ddoc=false`); everything else matches
> the distribution package (lib/headers/GIR/typelib/pkgconfig/udev rules/
> hwdb/metainfo).

## Publishing to the AUR

Pushing to the AUR requires an AUR account with your SSH public key attached.
The AUR authorizes pushes **per key**: if the key is not registered on the
account, the server answers `Permission denied (publickey)` even though the key
was offered correctly.

```bash
# 1. Register an account and add your SSH public key:
#    https://aur.archlinux.org/  →  My Account  →  SSH Public Key
#    The wiki recommends generating a dedicated key pair for this:
#      ssh-keygen -f ~/.ssh/aur
#    and adding ~/.ssh/config:
#      Host aur.archlinux.org
#        IdentityFile ~/.ssh/aur
#        User aur
#
# 2. Check the package name is still free (404 means available):
curl -s -o /dev/null -w "%{http_code}\n" https://aur.archlinux.org/packages/libfprint-omsmoc
#
# 3. Push (the package name must match the AUR repository name)
git clone ssh://aur@aur.archlinux.org/libfprint-omsmoc.git
cd libfprint-omsmoc
cp /path/to/OMS-fingerprint-linux/aur/libfprint-omsmoc/{PKGBUILD,.SRCINFO} .
git add PKGBUILD .SRCINFO
git commit -m "Initial import: libfprint with the OMS match-on-chip driver"
git push
```

Only `PKGBUILD` and `.SRCINFO` are pushed — the patch is referenced by URL.

After pushing, watch the build at
<https://aur.archlinux.org/packages/libfprint-omsmoc>. For any fix, bump
`pkgrel` and push a new commit; never amend a published one.

The full release procedure — regenerating the patch, publishing the patch tag,
rebuilding and verifying the package — is in
[docs/MAINTAINING.md](../docs/MAINTAINING.md).

## Verified

2026-09-12, Arch, on real hardware:

* `makepkg -fC` builds cleanly (1.94.100-1); the packaged
  `libfprint-2.so.2.0.0` contains `FpiDeviceOmsMoc`, and the hwdb entry
  `usb:v33A7p2388*` sits in the **supported** block (removed from
  known-unsupported)
* The system `fprintd` — **without** `LD_LIBRARY_PATH`; the process maps show
  `/usr/lib/libfprint-2.so.2.0.0`:
  * `fprintd-list` → device and enrolled prints recognized
  * `fprintd-enroll` → six stages, `enroll-stage-passed` → `enroll-completed`
  * `fprintd-verify` (enrolled finger) → `verify-match (done)`
  * `fprintd-verify` (unenrolled finger) → `verify-no-match (done)`
* `systemd-hwdb query 'usb:v33A7p2388*'` → `ID_AUTOSUSPEND=1` / `ID_PERSIST=0`
* The package binary contains no local build paths
